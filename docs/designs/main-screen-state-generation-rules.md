# 主界面状态生成规则

## 目标

统一主界面默认态各摘要字段的生成顺序与职责边界，避免实现时把事件、风险、路线、倾向、属性互相混写。

## 首页默认态字段

主界面默认态固定生成以下内容：

1. 顶部状态条
2. 当前事件
3. 人生摘要
4. 核心属性

## 生成顺序

推荐顺序：

1. 先确定顶部身份字段
2. 再确定当前事件正文
3. 再收敛风险结论
4. 再收敛路线结论
5. 再提取成长倾向
6. 最后挑选核心属性

## 字段职责边界

### 顶部状态条

- 回答：`我是谁，我在哪个阶段`
- 不回答：`我现在最危险的是什么`

### 当前事件

- 回答：`这回合发生了什么`
- 不回答：`系统层面的长期总结`

### 风险

- 回答：`我现在最该警惕什么`
- 不回答：`完整负面状态列表`

### 路线

- 回答：`我主要走在哪条人生方向上`
- 不回答：`当前临时情绪或偶发事件`

### 倾向

- 回答：`我最突出的成长重心是什么`
- 不回答：`所有属性概览`

### 核心属性

- 回答：`我现在最关键的几个数值大概如何`
- 不回答：`每项属性具体含义`

## 首页收口规则

- 事件是页面第一信息
- 风险是摘要第一判断
- 路线和倾向用于补足认知，不抢事件与风险
- 属性只保留数值，不展示说明

## 冲突处理

### 如果事件和风险表达重复

- 保留事件叙事在事件卡
- 风险只保留结论短句

### 如果路线和阶段冲突

- 顶部只展示当前更稳定、更长期的那一层
- 另一层后移到人生摘要或详情层

### 如果核心属性与倾向重复

- 允许重复同一数值一次
- 但首页不允许出现第二套完整属性组

## 验收标准

- 玩家不需要滚动即可理解主界面当前重点
- 每个字段都能回答一个明确问题
- 页面没有两个模块在重复承担同一职责
