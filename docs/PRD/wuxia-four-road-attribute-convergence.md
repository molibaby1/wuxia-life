# PRD: Wuxia Life 四道路与属性收敛

> 状态：已批准设计，尚未开始业务代码实施
> 范围：统一“公共属性 / 道路投入 / 身份 / 经历标记 / 结局”语义，并完成“经世”首个垂直切片

## 1. 背景与问题

当前系统同时存在 `PlayerState` 原始属性、`LifePath`、结构化 `routeStates`、路线 flag、身份检测、叙事 profile 路线和属性阈值结局。它们对“玩家正在过怎样的人生”使用了不同的来源和时间尺度。

现有代码还不是四道路模型：`RouteStateManager` 维护七个核心路线 ID，叙事 profile 定义八条路线和八个身份轨道，`GameEngineIntegration` 又通过属性阈值推导路线。结果是商人、官员、门派弟子、侠客、隐士等身份或落点，和道路投入、阵营、普通属性互相替代。

本 PRD 只解决概念真值与首个可验证闭环，不重写具体事件内容。

## 2. 目标

- 建立四条唯一道路：武道、经世、仕途、隐逸。
- 使道路表示人生投入与可达终局，而不是职业、阵营或单一属性。
- 使道路使用可见阶段：未定、试探、入局、深耕、终局。
- 使关键承诺决定入局，长期行为和成果负责验证或加速。
- 收敛玩家可见公共属性为：功力、体魄、学识、人脉、名望、侠义。
- 明确银两是资源，健康/疲劳是运行状态，身份和经历独立于道路。
- 让名望影响事件规模、外界压力和机会，不直接推进道路阶段。
- 完成经世道路的最小垂直切片，验证道路与商人身份可以分离。
- 保持旧存档、历史事件和已有 merchant 可玩链路在迁移期间可验证，不做无边界兼容。

## 3. 冻结的设计决策

### 3.1 公共属性

玩家可见的最小公共属性为：

| 属性 | 语义 |
|---|---|
| 功力 | 武学能力的公共表达；高功力不等于投入武道 |
| 体魄 | 长期生存、劳动和承诺承受力 |
| 学识 | 学习、治理、经营和理解能力 |
| 人脉 | 关系、协作和机会调度能力 |
| 名望 | 事件规模、压力和机会质量 |
| 侠义 | 道德立场与人生风格 |

旧武学子属性、`knowledge`、`comprehension`、`charisma` 等字段第一阶段可保留为内部实现，但不能继续作为多个“道路真相”。`money` 是资源；`health`、`energy`、`lifeStates` 是运行状态；`influence` 等重复概念不新增为核心公共属性。

### 3.2 道路

四道路及其核心承诺：

| 道路 | 核心投入 | 身份示例 |
|---|---|---|
| 武道 | 以修行、武学成就或传承为人生主项目 | 门派弟子、侠客、宗师 |
| 经世 | 长期建设生计、事业、组织或地方秩序 | 商人、医者、工匠 |
| 仕途 | 进入制度、官府或治理体系并承担公共权力责任 | 官员、名臣 |
| 隐逸 | 主动退出公共竞争并持续维持独立生活 | 隐士、山林高士 |

道路阶段统一为：

| 阶段 | 结构化状态 | 规则 |
|---|---|---|
| 未定 | `inactive` | 没有道路承诺 |
| 试探 | `temporary` | 有行为倾向，但不能决定终局 |
| 入局 | `active` | 完成一次关键道路承诺 |
| 深耕 | `locked_in` | 承诺得到持续行为或结构性成果验证 |
| 终局 | `completed` | 只有结局确认后成立 |

`turned` 和 `failed` 是历史结果，不是普通阶段。首阶段最多支持一条主道路和一条有限副道路，不建立组合矩阵。

### 3.3 终局

四个终局原型为：武道宗师、经世巨擘、定国名臣、隐逸高士。终局必须至少同时依赖道路阶段与道路成果证明，不能只依赖钱、功力、名望或单个 flag。

首阶段只保留三种组合候选作为后续方向：武道+仕途、经世+仕途、武道+经世。本阶段不实现组合终局。

## 4. 范围

### In Scope

- 统一道路、属性、身份、经历、结局的状态来源和命名。
- 将结构化路线生命周期收敛到四道路。
- 将关键选择映射为道路承诺，而不是直接把身份或属性当道路。
- 保留旧字段和历史 flag 的一次性迁移入口，不进行全量批量重命名。
- 让身份系统不再覆盖道路状态，也不再用单一身份替换所有既有身份。
- 让人生记忆、主界面摘要、属性面板和结局页面读取同一道路真值。
- 以现有商路内容完成“经世”首个垂直切片。
- 为迁移、身份独立、记忆展示、结局和商路切片增加最小测试。

### Out of Scope

- 不重写具体事件文本、选项内容或事件节奏。
- 不一次性把四条道路全部做成完整内容线。
- 不新增通用路线框架、插件化配置、扩展点或第二套 `roadScore`。
- 不立即删除所有旧属性、旧 flag、旧结局或历史记录。
- 不实现完整组合成就矩阵。
- 不重做 P18/P19 遗产与历史记忆系统，只调整其读取的道路输入。
- 不进行 UI 大改；只做信息来源和必要展示调整。
- 不把现有测试绿色或路线闭环状态解释成四道路模型已经完成。

## 5. 用户故事

### US-001：建立四道路与公共属性规范

**描述：** 作为开发者，我希望有唯一的道路和公共属性语义，以便后续事件、记忆、UI 和结局不再各自解释路线。

**验收标准：**

- [ ] 类型和核心状态明确区分公共属性、道路投入、身份、经历标记和运行状态
- [ ] 结构化道路 ID 只允许 `martial`、`statecraft`、`official`、`hermit` 四个规范 ID，显示名分别为武道、经世、仕途、隐逸
- [ ] 道路阶段复用 `inactive`、`temporary`、`active`、`locked_in`、`completed`，不新增重复的数值道路分数
- [ ] 公共属性的玩家可见规范名为功力、体魄、学识、人脉、名望、侠义
- [ ] `money`、`health`、`energy`、`lifeStates` 不被标记为道路投入
- [ ] 类型检查通过

### US-002：实现道路承诺与阶段迁移

**描述：** 作为玩家，我希望道路阶段由关键人生承诺和后续成果推动，而不是被某个普通属性阈值偷偷决定。

**验收标准：**

- [ ] 关键选择可以产生明确的道路承诺记录
- [ ] 没有关键承诺时，普通行为最多只能产生试探阶段
- [ ] 道路进入 `active` 后，事件可以读取道路阶段，而不是读取旧路线别名
- [ ] 道路进入 `locked_in` 必须存在承诺和行为/成果证明
- [ ] `reputation` 的变化不会单独推进道路阶段
- [ ] 旧路线 flag 的迁移只发生在明确的加载/快照边界，不在每个事件门槛中永久保留双轨判断
- [ ] 路线生命周期测试通过
- [ ] 类型检查通过

### US-003：拆分身份与经历

**描述：** 作为玩家，我希望“商人、医者、门派弟子、官员”等身份可以独立存在，而不会自动改变我的人生道路。

**验收标准：**

- [ ] 身份系统可以记录商人、医者、门派弟子、官员等身份/组织落点
- [ ] 身份变化不会重置或覆盖道路阶段
- [ ] 同一经世道路下，商人和医者可以拥有不同身份，但道路仍是经世
- [ ] `establish_sect`、`become_official`、`retired` 等结果被作为成果或经历使用，不单独等同道路完成
- [ ] `LifePath.faction` 和 `sect` 不再作为四道路 ID
- [ ] 身份与关键选择测试通过
- [ ] 类型检查通过

### US-004：统一人生记忆与主界面展示

**描述：** 作为玩家，我希望人生摘要、属性面板和反馈中的道路、阶段、身份、名望含义一致，以便理解自己正在走什么人生。

**验收标准：**

- [ ] 人生记忆摘要显示规范道路名和道路阶段
- [ ] 人生记忆摘要将身份、经历、关键承诺与道路分开显示
- [ ] 主界面显示名望，并说明其影响的是规模、压力或机会，而不是道路投入
- [ ] 路线反馈读取结构化道路状态，不再只比较原始 route flag
- [ ] 结局页面可以显示道路终局原型和身份/经历摘要
- [ ] 现有 merchant 可见成长展示不回退
- [ ] 类型检查通过
- [ ] 使用浏览器测试技能验证 UI 展示

### US-005：将结局绑定到道路证明

**描述：** 作为玩家，我希望结局反映我实际投入的人生道路，而不是单纯因为钱多、功力高或有一个历史 flag 就获得终局。

**验收标准：**

- [ ] 武道、经世、仕途、隐逸分别有可识别的终局原型
- [ ] 每个道路终局至少检查道路阶段和一道路成果证明
- [ ] `richest_man` 不再仅凭钱和商业 flag 直接替代经世完成
- [ ] `martial_god`、`sect_founder` 等旧终局可以映射为武道变体或成果，而不是新增道路
- [ ] 中性结局和全局失败结局仍可独立于道路运作
- [ ] 结局系统测试通过
- [ ] 类型检查通过

### US-006：完成经世首个垂直切片

**描述：** 作为玩家，我希望通过现有商路内容明确进入经世、持续经营并获得经世终局资格，同时商人身份仍保持独立。

**验收标准：**

- [ ] 一个现有商路关键选择可以将玩家从试探推进到经世入局
- [ ] 商人身份与经世道路同时显示，但两者来源不同
- [ ] 经营行为或已有成果标记可以推动经世深耕
- [ ] 名望影响事件规模、外界压力或机会，不直接提升经世阶段
- [ ] 经世终局要求道路阶段加经世成果证明，不只检查 `money`
- [ ] 同一道路的商人与医者状态夹具可以证明身份不改变道路阶段
- [ ] 现有 merchant 路线测试通过
- [ ] 类型检查通过
- [ ] 使用浏览器测试技能验证主界面、人生摘要和结局展示

### US-007：完成窄范围回归与迁移证明

**描述：** 作为维护者，我希望用窄测试证明迁移没有破坏存档、人生记忆和已有商路体验，并明确剩余风险。

**验收标准：**

- [ ] 路线生命周期、关键选择、身份、人生记忆、结局和快照测试通过
- [ ] merchant 可见成长与 native endgame 相关测试通过
- [ ] 旧存档至少有一条迁移夹具，能得到规范四道路状态
- [ ] 生成一份迁移边界与残余风险报告
- [ ] 不运行与本范围无关的全量内容重构
- [ ] 类型检查通过

## 8. 成功标准

- 代码中存在唯一可追踪的四道路状态来源。
- 名望、身份、经历和道路阶段在状态、记忆、UI、结局中语义一致。
- 经世垂直切片能完成“承诺 → 入局 → 深耕 → 终局资格”的可见闭环。
- 商人身份不是经世道路的别名；名望不是道路投入的别名。
- 现有商路可见成长、存档快照和相关结局测试不回退。

## 9. 暂缓问题

- 四道路之外是否允许某些完全独立的生活方式结局。
- 组合成就的具体奖励和终局文案。
- 武道与经世是否共享部分传承/组织成果。
- 旧 `scholar`、`hero`、`wanderer` 路线在所有历史事件中的最终文案映射。

这些问题不阻塞经世首个垂直切片，但在扩展第二条道路前必须重新确认。
