# Wuxia-Life Game Product Foundation

> 状态：当前游戏最高层产品规范（Human accepted：2026-10-09）
>
> 职责：定义游戏产品定位、核心体验、人生演化闭环、领域职责和架构边界。具体江湖人物、经济、人物关系、家庭等语义由下级正式规范与 Contract 承担，不在本文重复定义。

## 1. 产品定位

Wuxia-Life 是一款以人生经历为内容载体、以时间推进为基础、以玩家选择与持续投入为主要驱动力的交互式武侠人生模拟游戏。

玩家在不断变化的人生处境中，通过行动、重要选择、长期积累以及无法完全控制的机缘，塑造一段具有独特经历、真实后果和长期意义的人生。

事件是人生内容的主要载体，但游戏的核心价值不是事件播放，而是让玩家感受到：**过去的行动与选择塑造现在的人生，现在的选择又可能改变未来。**

## 2. 核心玩家体验

产品同时支持三个相容的体验层次：

1. **基础人生：**玩家无需掌握复杂机制，也能通过普通行动、选择与事件经历成长、转折和反馈。普通人生不因缺乏稀有成就、特殊身份或理想化结果而被视为失败或不完整。
2. **深度塑造：**长期投入、关键选择和不同方向的交叉组合形成可理解的人生差异。努力应改变机会与轨迹，但不自动保证能力、身份或成功。
3. **长期探索：**低频、罕见、传奇性及非典型经历可以增加探索价值与重复游玩的差异；特殊机缘必须服从正式因果规则，不是基础体验有意义的必要条件。

**过程中的真实反馈是核心；人生回顾是可选的终局呈现。**玩家应在游玩过程中理解选择的即时后果、阶段成果与多年后的回响。Life Milestone 是承载重要成长、中性经历、挫折与转折的核心长期反馈与记录机制。人生结束时可以从可靠的里程碑及其事实依据组织简洁回顾，但不强制设置独立的人生评价或总结系统（PD-128）。

## 3. 基础人生演化闭环

```text
当前人物与世界事实 + 已发生的历史 + 当前时间
→ 合法行动机会与事件
→ 玩家行动、选择或正式事件结算
→ 真实状态变化与历史积累
→ 可感知的即时反馈、阶段成果与后续回响
→ 下一阶段的人生演化
→ 人生正常结束；可选地依据里程碑回顾这一生
```

这是**产品因果关系**，不是对 Runtime 调用顺序、统一状态机或新 Schema 的实施授权。游戏应同时保留玩家主动塑造人生的空间与不完全受玩家控制的变化。

### 3.1 人生主循环与玩家／世界权责

**主动投入与选择、世界自主变化共同驱动人生，不以行动次数与事件数量按比例分配体验。**玩家能够决定自己有权决定的行动、时间投入和重要承诺；不能控制世界只发生有利之事、保证结果或代替其他具体人物作出私人决定。世界可独立带来机会、限制、遭遇、损失及罕见机缘，但不得凭空宣称玩家已自愿作出重大承诺。

长期投入和重要选择应通过真实事实与条件影响后续可能性，不保证成功、剧情保护或强制补偿。平稳而无显著事件的人生阶段同样合法。世界自主性不意味着必须建立实时 NPC 模拟、全球经济模拟或命运评分轴；利用合法事件、正式效果与历史因果即可提供必要体验（PD-129）。

### 3.2 人生阶段与长期连续性

童年、青年、中年与晚年是可能性和处境逐渐变化的人生阶段，**不是必须完成的剧情章节或固定任务列表**。年龄、时间与处境可以改变选择机会、责任、约束与风险；时间体现机会成本、真实积累及不可逆的经历。

连续性优先依靠**当前正式事实、发生过的历史、必要的持久结果和可回顾的里程碑**。后续内容如回应过去，必须有可靠因果；但不是每件重要经历都必须有续集、远期回报或补偿。不得为了跨年龄剧情建立通用 StoryArc 状态机或第二套人生进度状态（PD-129）。

### 3.3 当前单角色优先

当前优先完善**单个人物的一生**：出生、成长、主动生活、世界遭遇、重要选择、人生印记与正常结束。人物的人生事实及已获得里程碑不自动成为新人物的事实。

跨人物玩家档案、历史成就聚合、出生设定解锁、传承点数及跨局奖励均为**未来可选方向**，本阶段不预选方案，不设定积分、账号、继承或元进度规则。未来如有跨局机制，须重新裁决其对人物人生独立性、开局公平及重复游玩的影响（PD-129）。

## 4. 基础领域的职责与边界

- **人生演化机制：**承担时间推进、行动与选择、事件资格及调度、合法效果结算、历史记录和正式终局处理的共性职责。不直接替某个世界领域规定角色价值或成功标准。
- **人物与世界事实：**承担人物能力、投入、实践、特质、当前处境、身份、关系及持久世界事实的正式定义。同一事实只有一个 canonical source；具体含义服从对应领域权威。
- **世界与内容领域：**定义武侠世界的规则、人物、关系、经济、组织、事件、特殊机缘及合法结果。不同领域可以共同参与一件事，但不得因此发明重复的成长、状态、关系或结算机制。
- **玩家体验与反馈：**以 Life Milestone 作为人生核心长期反馈与记录机制，从正式状态、结算结果和历史表达当前处境、获得结果、阶段成果与长期回响，允许正面、中性及负面人生印记；不得为了叙事完整伪造事实。游戏结束能力属于运行/结算职责；终局里程碑回顾是可选的只读呈现，不要求独立的人生评价分类体系（PD-128）。

这些是**产品责任**而非代码目录、服务边界或必须对应的一对一模块。跨领域协作不意味着跨越对方的语义所有权。

## 5. 四项长期架构原则

### 5.1 领域单一职责

每个领域必须具有清晰的语义归属、输入依赖、合法变化来源、输出消费者及禁止边界。领域可以读取其他领域已经存在的合法事实，但不得重复创建相互竞争的事实来源或平行机制。

### 5.2 事实与结算分离

领域规范定义事实的含义、成立条件和合法变化边界；正式行动与事件结算负责执行变化。

**当前事实**说明现在仍然成立什么；**历史**证明过去发生过什么；**派生解释**帮助玩家理解事实与历史。这三者可以共同描述一次经历，但不能相互替代或形成第二套 canonical state。

### 5.3 反馈只解释事实

即时反馈和 Life Milestone 必须依据可靠的实际结算及历史生成，不得反向修改人物状态、历史、事件资格或终局。未来若提供里程碑回顾，也必须遵守相同的只读解释边界。

当前已有 Ending 状态的合法写入仍属正式结算；对 Ending 的展示和任何人生回顾均属派生解释。PD-128 取消了将独立人生总结或评价性终局分类作为当前硬性产品目标的要求，但不自动移除现有 Ending Runtime 或 Schema。

### 5.4 主题复用延迟抽象

当前实现目标是**武侠人生**。时间、人物、行动、事件、事实、结算和反馈具有潜在的跨主题共性，但不提前建设多世界平台、插件体系、通用 NPC 模拟或任意可配置规则引擎。

四项投入、六项核心属性及其他江湖规则继续由 [Player Model](player-model.md) 定义，不要求未来所有主题机械复用相同数量和含义。只有真实第二主题需求出现，才重新判断哪些工程抽象确有必要。

## 6. 产品评价标准

新增或调整领域、规则和内容时，先判断：

1. 是否服务于核心玩家体验，且让行动、选择或人生经历具有可理解的意义？
2. 是否遵守真实因果、已有历史及正式事实归属？
3. 是否尊重各领域既有 Contract，不擅自创造同义状态或隐藏成长机制？
4. 是否以当前必要性证明复杂度，而非为了未来可能性提前泛化？
5. 是否能通过明确产品语义及合理的玩家可见证据验证？

局部功能运行成功、测试通过、事件数量增长或 AE workflow 完成，不单独证明游戏的产品设计正确。

## 7. 权威与辅助工作流

本文件是 **Wuxia-Life 游戏产品领域的最高层产品规范**。

- [Player Model](player-model.md) 位于本规范之下，负责江湖人物模型；经济、重要人物与人物关系、家庭与子女等已批准领域 Contract 继续在其委托范围内有效。
- 时间、行动、事件、结算、持久化、反馈及其他机制继续遵循各自当前有效的 Product Decision、Contract 与 Schema。
- [Auto Evolution Model](auto-evolution-model.md) 是**独立的辅助工作流规范**，规定 AE 的组织、权限和执行语义，不与本文件竞争游戏产品定位的决定权。AE 与 Content Authoring 涉及游戏内容时，必须遵守本文件及相应游戏领域权威。

新规范不自动废止任何具体的已批准规则；若发现实质冲突，应明确报告并经过 Human 裁决，不得自行推断历史规则已失效。

## 8. 非目标与实施边界

本文件**不直接授权**：

- 修改 Runtime、Schema、API、Snapshot、Event 或现有玩法逻辑；
- 未经单独产品裁决重新设计既有属性、Status、Trait、Habit、经济、关系或 Milestone 语义；Milestone 核心反馈方向已由 PD-128 单独批准，具体实现仍须有界授权；
- 新建多世界引擎、通用 NPC 模拟、通用任务线或新状态机；
- 批量增加事件、奇遇、成就、稀有度系统或新的反馈事实来源；
- 全面 UI 改版、数值重平衡、终局重做，或扩大 AE / 内容生成器权限。

当前阶段首先完成游戏**基础产品决策与权威文档的全局收敛**，明确单角色主循环、世界自主性、人生连续性和里程碑反馈的共同边界；之后才统一审查活跃实现差异，并另行授权有界迁移。当前收敛阶段不自动启动领域专项治理、代码修改或 AE 能力扩张（PD-129）。
