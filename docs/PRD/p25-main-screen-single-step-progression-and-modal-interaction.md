# PRD: P25 主界面单次推进与弹层交互收口

## 1. 背景

主界面首轮 UI 改版已经解决了首屏层级、重复属性和主操作下沉问题，但实际试玩后仍暴露出三个核心交互缺陷：

1. 同一阶段经常需要先点击一次 `继续`，看到本次结果文案后，再点击第二次 `继续` 才真正进入下一阶段，节奏拖沓。
2. 主动选择类事件仍然落在页面下方，而随机/剧情事件位于上方，导致玩家需要在同一主循环里来回切换注意力。
3. 二级信息仍然通过页面滚动访问，尤其是人生摘要和完整属性，交互成本偏高，不符合 H5 / 小程序紧凑型单屏体验目标。

这次改版不重做整体视觉系统，也不重写后端协议。目标是在现有主界面改版基础上，把主循环进一步收口为更轻、更直接、更适合移动端的单屏交互。

## 2. 目标

1. 将“本次结果展示”和“进入下一可交互阶段”合并成一次主操作。
2. 保留事件/行动结果的可见性，但不再要求玩家为结果展示额外点击一次 `继续`。
3. 将主动选择类事件与随机/剧情事件统一放到顶部主事件区。
4. 用弹层/抽屉替代滚动定位式二级交互，尽量让主界面交互在单屏内完成。

## 3. 非目标

- 不重做整体视觉风格。
- 不新增玩法、字段或数值系统。
- 不修改事件语义、成长语义或后端存档边界。
- 不改动其他页面的整体信息架构。
- 不为了兼容旧交互保留“双继续”流程。

## 4. 范围

### 4.1 In Scope

- 主界面中剧情选择、主动行动、被动推进、扰动叙事、阶段小结的推进方式重构。
- 本次结果展示从阻塞页面改为非阻塞弹层/浮层。
- 主动选择区上移到顶部主事件卡。
- 人生摘要、完整属性从滚动跳转式访问改为弹层或抽屉式访问。
- API 模式与本地模式的交互行为保持一致。

### 4.2 Out Of Scope

- 事件内容改写。
- 报告系统与模拟器逻辑扩展。
- 其他页面的弹层体系统一重构。

## 5. 关键设计判断

### 5.1 单次推进

用户每进行一次有效主操作后，界面应直接推进到下一个可交互阶段。

“本次结果”不再作为独立阻塞页面存在，而是作为结果弹层附着在新阶段之上展示。

### 5.2 结果弹层

结果弹层用于承载：

- 剧情选择结果
- 主动行动小结
- 扰动叙事
- 被动阶段/阶段小结

弹层关闭不影响主循环继续，结果展示与主流程推进解耦。

### 5.3 顶部主事件区统一

主动选择与剧情选择都在顶部主事件区出现，避免玩家上下滚动寻找交互入口。

### 5.4 单屏二级交互

人生摘要、完整属性等二级内容使用弹层/抽屉打开，不再依赖 `scrollIntoView` 或长页面滚动。

## 6. 用户故事

### US-001 单次推进结果保留

作为玩家，我希望每次点击一次主操作后，能直接进入下一阶段，同时仍然看得到本次结果，而不是被迫再点一次继续。

验收标准：

- 剧情选择后不再额外点击第二次 `继续`
- 主动行动后不再额外点击第二次 `继续`
- 被动阶段推进后不再额外点击第二次 `继续`
- 本次结果仍然可见

### US-002 顶部统一交互区

作为玩家，我希望主动选择与剧情选择都出现在顶部主事件区，而不是滚到底部寻找按钮。

验收标准：

- 主动选择按钮位于顶部主事件卡
- 剧情选择按钮位于顶部主事件卡
- 页面底部不再承担主循环选择职责

### US-003 弹层替代滚动

作为玩家，我希望人生摘要和完整属性通过弹层查看，而不是滚动跳转。

验收标准：

- 人生摘要可通过弹层查看
- 完整属性可通过弹层或抽屉查看
- 主界面不再通过滚动定位这两个区域

### US-004 API / 本地模式一致性

作为维护者，我希望 API 模式和本地模式在主界面推进交互上保持一致。

验收标准：

- 两种模式都不再出现“双继续”推进
- 两种模式都保留结果可见性
- 两种模式的顶部交互区位置一致

## 7. 验收门禁

- 选择一次剧情选项后，直接进入下一可交互阶段，并能看到结果弹层。
- 选择一次主动行动后，直接进入下一可交互阶段，并能看到结果弹层。
- 人生摘要与完整属性均可通过弹层/抽屉查看。
- 顶部主事件区承担所有主循环交互入口。
- H5 与小程序窄屏下，首屏主循环仍然稳定。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 自动推进过快导致结果一闪而过 | 玩家丢失反馈感知 | 结果保存在弹层中，默认展开 |
| API 与本地流分叉 | 交互不一致 | 同时改两套前端推进逻辑 |
| 弹层过多造成打扰 | 体验变跳 | 仅将结果、人生摘要、完整属性做成弹层 |
