# Visible Growth Scope Contract

## 目的

锁定“可见成长补强”这一轮工作的边界，防止实现阶段从体验补强滑向系统扩张。

本文档只回答：

1. 这一轮允许做什么
2. 这一轮明确不能做什么
3. 做到什么程度就算完成

---

## 一、本轮阶段定位

本轮是：

- **成长感补强阶段**
- **样板闭环阶段**
- **现有 `habit` 能力的体验强化阶段**

本轮不是：

- 商路线全面重做阶段
- 武功数值重构阶段
- 技能系统设计阶段
- 多路线并行扩容阶段
- 新系统研发阶段

---

## 二、本轮唯一核心目标

在一条样板路线中，证明以下闭环对玩家是可感知的：

`行为 -> habit 累积 -> 可见成长确认 -> 新机会 / 新挑战 / 新分岔`

如果这条闭环没有成立，本轮就不算完成。

如果这条闭环已经成立，本轮就不必继续扩张。

---

## 三、本轮允许改动的层

### 1. 现有 `habit` 驱动链路

允许：

- 强化已有 `habit` 的使用方式
- 调整 `habit` 到可见确认之间的连接
- 增强 `habit` 到后续资格之间的承接

不允许：

- 新增第二套人格/习惯容器

### 2. 玩家可见确认层

允许：

- 强化已有摘要表达
- 强化已有选择反馈表达
- 增加轻量的成长确认节点

不允许：

- 新建大型独立角色面板
- 引入新的复杂展示体系

### 3. 样板路线内的窄内容补强

允许：

- 为样板路线补一个最小成长确认节点
- 为样板路线补一个最小承接节点
- 为样板路线补一个最小验证闭环

不允许：

- 顺手扩成整条路线重做
- 顺手并行补第二条第三条路线

### 4. 验证与证明层

允许：

- 增加针对这条闭环的窄验证
- 增加样板路径的证明材料

不允许：

- 把本轮扩成全生命周期大验收

---

## 四、本轮样板路线

本轮固定只使用：

- `merchant_house`

原因：

- 它已暴露出最清晰的体验问题
- 它已具备一定 `businessHabit` 基础
- 它是当前最适合验证非武路线成长闭环的样板

本轮不处理：

- 多条出身并行补强
- 普通出身全量迁移
- 医术、门派、江湖名宿同步跟进

---

## 五、本轮明确禁止项

### 1. 禁止新建独立“性格自动成长系统”

理由：

- 与现有 `habit` 重复
- 必然扩大架构复杂度

### 2. 禁止完整商路线重写

理由：

- 会把样板验证阶段扩成路线大修
- 失去“先证闭环”的边界

### 3. 禁止完整武功数值重构

理由：

- 当前主问题不是武功数值实现本身
- 会把成长补强阶段拖入大迁移

### 4. 禁止开启技能系统设计或实现

理由：

- 会引入新的复杂层
- 会冲淡本轮的主目标

### 5. 禁止并行推进多条路线

理由：

- 容易把样板验证变成面状铺开
- 难以确认哪种改动真正解决了成长感问题

### 6. 禁止按年龄直接自动涨点

理由：

- 不符合当前已确定的成长模型
- 会削弱“行为塑形”的中心地位

---

## 六、本轮完成标准

本轮完成必须同时满足以下条件：

1. 玩家能在样板路线的早期阶段明确感到“我最近在往某个方向成长”
2. 这种成长确认来自前期重复行为，而不是年龄自然增长
3. 成长确认之后，出现至少一个新的机会、挑战或分岔
4. 整体改动仍然依赖现有 `habit`，没有引入平行系统
5. 本轮结果可以被后续路线复用为模式

只满足其中一部分，不算本轮完成。

---

## 七、本轮之后的顺序

若本轮完成，后续顺序应为：

1. 商贾 10–15 岁关键分岔补强
2. 武功主显职责收敛
3. 其他非武路线复用同一成长闭环模式

在此之前，不应提前开启：

- 技能系统
- 全局属性大迁移
- 多路线同时扩写

---

## 八、一句话结论

这一轮只做一件事：用 `merchant_house` 证明现有 `habit` 足以支撑“可见成长闭环”；凡是不直接服务这件事的改动，都视为超出范围。
