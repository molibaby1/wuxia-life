# 2026-06-30 技能作为差异化表达容器的边界分析

## 1. 文档目的

在当前项目已经存在属性、天赋、habit、路线、flag、事件反馈等多层结构的前提下，分析未来如果引入“技能”，它应该承担什么，不应该承担什么。

本文档的目标不是设计完整技能系统，而是先解决一个更基础的问题：

**技能到底应该是“新的体验表达层”，还是“又一套新的复杂数值层”？**

如果这个边界不先收住，技能很容易成为下一轮过度设计入口。

---

## 2. 当前系统里已经存在的“差异化载体”

在讨论技能之前，先明确仓库里已经有哪些东西在承担人物差异化。

### 2.1 属性

当前属性已经负责：

- 能力强弱
- 条件门槛
- 事件资格
- 一部分玩家可见成长

例如：

- `martialPower`
- `charisma`
- `knowledge`
- `businessAcumen`

属性的核心职责应当是：

**回答“你强不强 / 够不够格 / 差多少”。**

### 2.2 天赋

当前天赋文档里，天赋已经被定义为：

- 出生时确定的成长潜能
- 属性成长速度修正
- 属性上限修正
- 初始属性修正

因此，天赋的核心职责其实已经很明确：

**回答“你天生更偏向哪种成长”。**

它更像先天倾向，而不是后天掌握的具体能力。

### 2.3 habit / lifeStates

当前 habit / shaping 轴主要负责：

- 长期行为塑形
- 半人格 / 半路径倾向
- 某些中后期 consequence 的门槛与解释

例如：

- `trainingHabit`
- `studyHabit`
- `businessHabit`
- `socialMomentum`

它们的职责更接近：

**回答“你是怎么一路活成现在这样的人”。**

### 2.4 路线 / 身份

路线系统主要负责：

- 人生主 arc
- 阶段性承诺
- 路线生命周期
- 玩家可理解的人生方向

例如：

- `route_orthodox`
- `route_demonic`
- `route_merchant`

其职责是：

**回答“你现在走的是哪条人生路”。**

### 2.5 事件 / choice feedback

体验治理文档已经反复强调：

- 变化不能只藏在 hidden state
- 玩家必须看到可理解的因果
- durable state 的 payoff 需要通过可见文本、可见事件、可见选项变化体现出来

因此，事件与反馈层负责：

**回答“刚才发生了什么，它为什么重要”。**

## 3. 技能最容易重复掉的区域

如果不先设边界，技能最容易和以下几层重复：

### 3.1 和属性重复

错误做法：

- 把“外功精通”“口才”“账房本事”继续做成另一套数值
- 既有属性数值，又有技能等级，又有技能熟练度

结果会变成：

- 属性回答强弱
- 技能也回答强弱
- 两套系统都在做门槛判断

这会直接复制当前武功属性 already-too-much 的问题。

### 3.2 和天赋重复

错误做法：

- 把“天生适合经商”“武学悟性高”“社交灵敏”这类先天倾向又塞进技能

结果会变成：

- 天赋在说你先天擅长什么
- 技能也在说你先天容易掌握什么

边界会非常模糊。

### 3.3 和 habit 重复

错误做法：

- 把“常年练功”“长期跑商”“习惯读书”做成技能树

结果会变成：

- habit 在记录长期行为塑形
- 技能又在记录长期行为积累

两者会争夺“后天形成的长期差异”解释权。

### 3.4 和路线重复

错误做法：

- 通过技能集合直接替代人生路线

例如：

- 有“魔功”“正道剑法”“商道经营”就默认等于走了那条路

这样会把人生路线压缩成 build 组合，而丢掉叙事线、承诺线、身份线的意义。

## 4. 技能更适合承接什么

如果技能不应该再做一套“强弱系统”，那它更适合承接的是：

### 4.1 可记忆的具体本事

技能最适合表达的，不是抽象能力值，而是：

- 你会不会某件事
- 你掌没掌握某种手段
- 你形成了哪种具体风格

例如：

- 基础剑式
- 轻身术
- 识货
- 看账
- 讨价还价
- 察言观色
- 配药
- 稳手缝合

这类内容的优势是：

- 容易记
- 容易写文案
- 容易做事件分支
- 比纯数字更有角色感

### 4.2 特定事件的解法权限

技能非常适合负责：

- 某个事件有没有特殊处理方式
- 某个选择有没有专属选项
- 某类风险有没有特殊缓解手段

也就是说，技能适合回答：

**“你有什么别人没有的解法？”**

而不是：

**“你的总战力是多少？”**

### 4.3 人物风格的表达标签

技能还适合做：

- 文案 flavor
- 当前目标文案变化
- life-memory / summary 的差异化句子来源

例如同样是商人：

- 一个靠“识货”
- 一个靠“盘账”
- 一个靠“人情经营”

这类差异很适合由技能驱动表达，而不一定要继续拆更多数值。

### 4.4 少量被动效果来源

如果技能带被动，最合理的也应是：

- 小而明确
- 易解释
- 不与主属性强弱争夺中心位置

例如：

- 更容易触发某类机会
- 某类事件损失略低
- 某类选择成功率略高

而不是：

- 再做一套庞大的乘区和成长公式

---

## 5. 技能不适合承接什么

### 5.1 不适合承接主成长数值

技能不应取代属性回答：

- 强不强
- 够不够
- 伤害多高
- 成长有多快

否则技能就会再次变成数值系统。

### 5.2 不适合承接先天倾向

技能不应回答：

- 你天生适不适合
- 你先天容易不容易学

这些更应由天赋承担。

### 5.3 不适合承接长期习惯塑形

技能不应回答：

- 你这些年一直在做什么
- 你长期偏向什么生活方式

这些更应由 habit / lifeStates 承担。

### 5.4 不适合直接代替路线系统

技能不应直接决定：

- 你的人生主 arc 是什么
- 你是否已经进入某条路线承诺

路线仍应通过路线事件、承诺节点、身份变化来建立。

## 6. 一个更清楚的职责切分

如果把几个系统按“回答不同问题”来切开，更清楚的边界应该是：

| 层 | 回答的问题 | 更适合由谁承担 |
| --- | --- | --- |
| 能力强弱 | 你强不强、差多少、够不够格 | 属性 |
| 先天倾向 | 你天生更容易长成什么样 | 天赋 |
| 长期塑形 | 你这些年是怎么活过来的 | habit / lifeStates |
| 人生主线 | 你正在走哪条路 | route / identity |
| 具体本事 | 你会什么特别手段 | 技能 |
| 当下因果 | 刚才发生了什么变化 | 事件 + feedback |

这张表最重要，因为它说明：

**技能最适合回答的是“你会什么”，而不是“你有多强”。**

## 7. 如果未来真的做技能，最安全的收口方式

### 7.1 技能先做“离散能力”，不要做连续成长条

比起：

- 技能等级 1–100
- 熟练度成长
- 技能树节点

更安全的第一步是：

- 有 / 没有
- 已掌握 / 未掌握
- 初阶 / 熟练 / 成形 这种少档位

因为离散技能更不容易和属性系统撞车。

### 7.2 技能先服务表达与分支，不先服务战斗公式

第一批技能更适合优先用于：

- 事件文本变化
- 特殊选项开放
- 角色总结差异
- 路线 flavor 分叉

不适合一上来就接：

- 复杂战斗计算
- 复杂收益乘区
- 多层数值堆叠

### 7.3 技能应优先补非武路线表达

如果现在就做技能，最该优先受益的其实不是武功，而是当前表达偏弱的非武路线。

例如：

- 商路：识货、盘账、周转、人情经营
- 社交：听话头、讲场面话、撮合、调停
- 学识：抄录、辨典、记方、设局

这样技能会成为“补平衡”的工具，而不是继续放大武功中心化。

### 7.4 技能应尽量挂在已有反馈面上

技能一旦引入，最好优先复用现有玩家可见面：

- choice feedback
- currentGoal
- life-memory
- summary
- route-related readable text

而不是再新开一整套厚重面板。

## 8. 三种技能定位方向对比

### 8.1 风味型技能

特点：

- 主要改变文案、选项和角色辨识度
- 弱机械，强表达

优点：

- 风险低
- 很适合当前项目
- 最不容易过度设计

缺点：

- 短期“数值爽感”不强

### 8.2 分支型技能

特点：

- 改变事件可用选项与解决路径
- 少量带来成功率 / 风险差异

优点：

- 能增强“我这个人有独特手段”的感受
- 和主动规划体验兼容度高

缺点：

- 需要严控数量，否则 authoring 成本会迅速上升

### 8.3 数值型技能

特点：

- 技能本身也成长
- 技能直接参与强弱计算

优点：

- build 感强

缺点：

- 最容易和属性重复
- 最容易重蹈过度设计
- 最不适合当前项目阶段

---

## 9. 当前建议判断

### 9.1 推荐的技能定位

如果未来要做技能，最推荐的定位是：

- **先做风味型 + 分支型**
- **暂不做主数值型**

### 9.2 推荐的承接边界

技能应优先承接：

- 具体本事
- 事件解法权限
- 路线 flavor 分化
- 少量被动特例

### 9.3 不推荐的承接边界

技能不应优先承接：

- 主战力拆分
- 成长倍率体系
- 长期习惯塑形
- 人生主路线判定

---

## 10. 最终结论

当前项目里，属性、天赋、habit、路线都已经各自承担了一部分差异化职责。

因此，未来的“技能”如果要成立，最重要的不是“再加一个系统”，而是：

**只让它补当前缺的那一层。**

这层最缺的，不是新的强弱数值，而是：

- 更可记忆的人物本事
- 更具体的事件解法差异
- 更清楚的非武路线表达

所以，技能最合理的边界是：

**作为“你会什么”的表达层，而不是“你有多强”的第二数值层。**
