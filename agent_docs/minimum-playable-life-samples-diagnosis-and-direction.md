# 最小可玩人生样本线诊断与改进方向

## 文档目的

本文档用于交接当前关于 `wuxia-life` 核心体验问题的诊断结论与后续优化方向。

它不是已审批的实施方案，也不是完整 PRD。后续会话应先读取本文档，再进入 `ralplan` / PRD / `prd.json` 拆解，避免重新发散到全量系统重构或单纯堆事件池。

## 当前核心判断

项目当前的主要问题不是“缺系统”，而是玩家还没有稳定感到自己在经历一条有欲望、压力、抉择、代价和回报的武侠人生线。

现有项目已经具备较多结构能力：

- 事件池与阶段事件
- 路线、身份、flag 与长期反馈
- 主动行动与成长倾向
- 选择反馈、人生摘要和回响文案
- 多层仿真 gate 与体验报告

这些能力能证明项目逐步“不坏”，但还不能直接证明它“好玩”。后续优化应先做出少量可感知、可复述、可验证的人生样本，而不是继续扩大系统面。

## 三个核心痛点

### 1. 强玩家欲望循环不足

玩家缺少持续明确的问题：

- 我想成为谁？
- 我正在赌什么？
- 我会失去什么？
- 下一步为什么非点不可？

当前的主动行动和事件反馈能给出数值、flag、路线变化，但还不够稳定地产生“追求目标、承担代价、等待回报”的心理牵引。

### 2. 事件调度替代剧情推进

当前项目有大量事件线和调度乘数。它们可以改善重复、节奏和覆盖率，但玩家体感容易变成“这一年抽到什么事件”，而不是“这一生正在奔向什么命运”。

后续应先用少量强样本线验证：剧情目标是否能统领事件，而不是让事件池自己拼出人生。

### 3. 反馈有信息但缺情绪和悬念

主界面已能展示数值影响、关系影响、路线变化和长期影响，但这些反馈仍容易像账本。

后续事件链需要把长期影响写成玩家能感知的叙事资产，例如：

- 新的债
- 新的敌人
- 新的机会
- 新的诱惑
- 不可逆的名声
- 日后会回来找你的承诺

## 技术方向判断

第一阶段不建议先重写 runtime。

现有 runtime 已经能承载最小可玩样本线需要的大部分能力：

- `ageRange`：固定年龄段触发
- `conditions`：基于属性、flag、路线状态做门禁
- `priority`：保护关键节点
- `mandatory` / `mainline` / `once` 标签：保护主线节点
- `flag_set`：写入长期后果
- `narrativeScheduling.routePoints`：描述路线节点
- 路线/身份解析：形成中期身份和阶段总结
- 主动行动：提供玩家主动塑形入口
- 仿真脚本和 gate：验证样本线是否稳定出现

因此，第一阶段应以剧情配置为主，辅以轻量展示映射和验证脚本。

只有遇到以下证据时，才考虑 runtime 改动：

- mandatory/mainline 节点仍无法稳定触发
- 同一路线节点无法顺利续上
- 关键选择无法表达失败回流
- UI 完全无法展示当前目标、压力或长期代价
- 仿真无法稳定复现三条目标路线

## 第一阶段最小可玩样本

建议先做三条 0-40 岁人生样本线。

### 样本线 A：正派武道

体验目标：玩家能感到自己从幼年练功、入门立志、被门派或江湖认可，到 40 岁前形成清晰正派武道身份。

应包含：

- 童年练功种子
- 少年阶段第一次被认可
- 青年阶段门派/江湖选择
- 中年阶段守正代价
- 40 岁身份总结

关键不是“武功变高”，而是玩家能记住自己为什么走正道，以及为此放弃了什么。

### 样本线 B：邪路偏锋

体验目标：玩家能感到邪路不是简单坏结局，而是一条带诱惑、风险、收益和社会代价的成长路径。

应包含：

- 童年狠劲或偏执种子
- 少年阶段第一次越界
- 青年阶段高收益诱惑
- 中年阶段名声、关系或健康代价
- 40 岁邪路身份总结

关键不是“变强但扣声望”，而是玩家能感到自己一步步被选择和后果推向邪路。

### 样本线 C：商路崛起

体验目标：玩家能感到自己从小本经营、结交人脉、承担风险，到 40 岁前形成商路身份。

应包含：

- 童年营商或帮工种子
- 少年阶段第一次赚到本钱
- 青年阶段商队/投资分岔
- 中年阶段财富与江湖义气冲突
- 40 岁商路身份总结

关键不是“银两变多”，而是玩家能感到财富带来选择权，也带来债务、人情和风险。

## 每条样本线的最低验收标准

每条样本线至少满足：

- 0-40 岁有 5 个关键节点
- 至少 2 个关键选择
- 至少 1 个失败或代价回流
- 至少 1 个中期身份信号
- 40 岁前有可辨认身份总结
- 玩家能在一次游玩后复述“这条人生为什么不同”

仿真验收至少包含：

- 固定 seed 下关键节点稳定出现
- 关键 flag 写入与后续事件条件能接上
- 路线身份不被无关事件覆盖
- 同年龄段不出现明显复读或低影响空窗
- 三条样本线之间具备可读差异

人工验收至少包含：

- 玩家是否知道自己当前追求什么
- 玩家是否感到选择有代价
- 玩家是否记得一个关键转折
- 玩家是否愿意继续到下一个阶段
- 玩家是否愿意重开另一条路线

## 明确非目标

本阶段不做：

- 全量人生模拟重构
- 全量事件池扩写
- runtime 平台化改造
- 大规模 UI 信息架构重做
- 全部路线和全部结局覆盖
- 把 gate PASS 当作“好玩”的唯一证明
- 为所有未来内容设计通用工作流引擎

## 后续计划建议

建议下一步进入 `ralplan --interactive`，产出正式 PRD 和 `prd.json`。

规划时应明确分成三类工作：

1. 剧情配置：新增或调整三条样本线的事件链、条件、flag、routePoints。
2. 轻量展示补齐：必要时补玩家可见 flag 文案、路线摘要、长期影响描述。
3. 验证脚本：新增三条样本线的固定 seed 仿真与人工 playtest checklist。

## 交接提醒

后续实施会话不要直接从“补事件”开始。应先确认三条样本线的章节目标、关键选择、代价回流和验收指标，再按 `prd.json` 的单故事顺序执行。
