# P64 Merchant Pressure/Payoff Scope Contract

> **Date:** 2026-06-28
> **Stage:** P64 Merchant Magnate Differentiated Pressure And Payoff
> **Branch:** `codex/p64-wuxia-merchant-magnate-differentiated-pressure-payoff`

---

## 1. Purpose

This scope contract establishes the explicit boundaries for P64 to prevent it from growing into a full merchant second-wave content buildout. P64 is a **bounded densification stage** focused solely on adding minimum differentiation to the existing `magnate_midlife_pressure` and `magnate_payoff` stages.

---

## 2. P64 Scope: Pressure and Payoff Differentiation Only

P64 is limited to:

### 2.1 Allowed Changes

| Category | Allowed |
|----------|---------|
| **Configuration** | Light markers or expression flags for pressure/payoff differentiation |
| **Expression** | Origin-specific text in `merchantCurrentGoal()`, `magnate_midlife_pressure` event, `magnate_payoff` event |
| **Proof** | One comparison-style targeted proof artifact showing pressure/payoff differentiation |
| **Tests** | Narrow regression tests covering marker, expression, and comparison assertions |

### 2.2 Allowed Layers Detail

- **Event text differentiation:** Add bounded origin-specific flavor to `magnate_midlife_pressure` and `magnate_payoff` event text
- **Expression surface differentiation:** Update `merchantCurrentGoal()` to show origin-specific pressure/payoff emphasis
- **Light markers:** Use existing bridge flags (`apprentice_merchant_bridge_crossed`, `tavern_merchant_bridge_crossed`, `peasant_merchant_bridge_crossed`) to drive differentiation
- **Narrow tests:** Reuse existing merchant/bridge test harnesses for regression coverage

The following are explicitly **NOT** in P64 scope:

### 3.1 New Large Chains Forbidden

| Forbidden | Reason |
|-----------|--------|

| New merchant content wave | Out of bounded densification scope |
| Full merchant economy system | Out of scope per PRD non-goals |
| New merchant map/chamber/platform | Out of scope per PRD non-goals |
| New merchant职业/技能系统 | Beyond pressure/payoff differentiation |

### 3.2 System Changes Forbidden

| Forbidden | Reason |
|-----------|--------|
| Merchant framework changes | Only expression/configuration changes allowed |
| Gate architecture modifications | Gate architecture is healthy reuse; must remain intact |
| Flag naming pattern changes | Existing patterns must be preserved |
| New event categories | Only modifying existing magnate events |

### 3.3 Full Merchant Universe Buildout Forbidden

P64 does NOT include:
- Full merchant combinatorial exhaust testing
- Full lifetime merchant sandbox
- Complete merchant content wave
- Merchant-specific habit trajectory densification beyond pressure/payoff
