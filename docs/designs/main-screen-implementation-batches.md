# 主界面开发实施计划

## 目标

将主界面改版任务收敛为三个可执行开发批次，便于分配给不同会话或工程师，并保证每一批次结束后都有可验证结果。

## 批次划分原则

- 每个批次都必须有清晰边界
- 优先先解决首屏主流程问题，再处理信息层级，最后做细节收口
- 每个批次结束后页面都应处于可继续迭代状态

## Batch 1: 首屏主流程重构

### 目标

先解决主界面最严重的问题：`继续` 按钮不可首屏直达、事件卡位置过低、重复属性干扰主流程。

### 包含任务

- Task 1: 删除首页重复属性区
- Task 2: 上移当前事件卡与继续按钮
- Task 3: 压缩顶部状态条

### 实施重点

- 页面结构从“属性优先”改为“事件优先”
- 删除白底重复属性区
- 将当前事件卡提升到顶部状态条下方
- 保证 `继续` 成为页面唯一主按钮
- 控制顶部区域高度，释放首屏空间

### 完成标准

- 基准移动端视口下，进入页面无需滚动即可看到完整 `继续`
- 页面默认态不再出现两套重复属性
- 顶部状态条不再挤压主内容区域

### 验证方式

- 基准视口下截图验证首屏布局
- 检查首页默认 DOM/渲染结构，确认重复属性区已移除
- 手动确认 `继续` 为唯一高权重操作

## Batch 2: 信息层级与摘要重构

### 目标

在首屏主流程理顺后，将首页信息改为“摘要优先”，让玩家快速理解状态而不是被属性百科淹没。

### 包含任务

- Task 4: 重构人生摘要卡
- Task 5: 新建核心属性摘要卡
- Task 7: 统一按钮层级

### 实施重点

- 将人生摘要重写为三条结论信息
- 核心属性区改为 `2 x 3` 栅格
- 首页属性只展示名称与数值
- 次按钮统一弱化，不与 `继续` 竞争

### 完成标准

- 玩家进入页面后可在数秒内读到路线、风险、倾向
- 首页属性区不再出现解释句、进度条和风味文案
- 按钮层级清晰，视觉重心稳定

### 验证方式

- 截图核对首页模块顺序与轻重关系
- 文案审查，确认首页默认态只保留事件、状态结论、核心数值
- 检查按钮样式与层级是否符合规范

## Batch 3: 属性详情层与适配收口

### 目标

将详细属性迁入二级层，并完成 H5 / 小程序环境下的安全区与窄屏适配。

### 包含任务

- Task 6: 将详细属性迁入抽屉或折叠区
- Task 8: 响应式与安全区收口

### 实施重点

- 新建完整属性详情层
- 分组展示战斗 / 江湖 / 成长 / 资源
- 首页默认态不再出现长属性说明
- 检查窄屏、高度不足、长文案、长标签、极端数值场景

### 完成标准

- 首页与详情层职责分离明确
- `全部属性` 入口工作正常
- H5 与小程序下首页结构稳定，不出现按钮遮挡和内容挤压

### 验证方式

- 手动展开 / 收起属性层，检查交互路径
- 多种移动端视口下检查首屏可见性
- 检查顶部与底部安全区下按钮和卡片是否被遮挡

## 推荐交付节奏

### 方案 A: 单人串行

1. 先做 Batch 1
2. 验证首屏主流程
3. 再做 Batch 2
4. 最后做 Batch 3

适用场景：

- 由一个会话或一个前端连续完成
- 需要最大限度降低合并冲突

### 方案 B: 双线并行

- 一人负责 Batch 1
- 一人预先准备 Batch 2 所需的文案和组件拆分
- 待 Batch 1 稳定后合流推进 Batch 2 与 Batch 3

适用场景：

- 希望缩短总改版周期
- 团队内已有明确组件负责人

## 每批次交付物

### Batch 1 交付物

- 调整后的首页结构
- 事件卡首屏版式
- 去重后的首页属性展示

### Batch 2 交付物

- 人生摘要卡
- 核心属性摘要卡
- 首页按钮层级统一结果

### Batch 3 交付物

- 完整属性详情层
- H5 / 小程序适配结果
- 安全区和窄屏验证结果

## 风险提示

- 如果先做视觉细节而不先做 Batch 1，容易陷入“旧结构上抛光”的无效改版
- 如果首页摘要层直接复用旧属性组件，容易把解释文案再次带回首页
- 如果未单独验证小程序安全区，主按钮可能在真机环境下被底部区域挤压

## 结束判定

主界面改版可以认为达到首轮完成的条件：

1. 首屏能完成主循环操作
2. 默认态没有重复属性
3. 详细属性已从首页退出
4. H5 与小程序环境下结构稳定
5. 玩家能快速理解当前事件、风险与核心状态
