# PRD: P7 主动人生规划与属性认知体验重构

## 1. 背景

现有体验治理已经覆盖事件质量、路线反馈、引擎契约、无头运行与存档/API 基础，但当前可玩体验仍存在一个更根本的问题：玩家的人生主要由随机或半随机事件推动，缺少主动安排人生方向的能力。

当前问题集中在六个方面：

- 人生缺少可规划目标，玩家难以理解自己正在走向哪里。
- 时间推进过粗，普通事件也会消耗一年，导致专注投入、持续养成和阶段性计划无法成立。
- 选项优劣过于直观，容易变成“永远选择数值最优项”。
- 属性虽然存在并被部分事件读取，但玩家难以理解属性能做什么、差多少、为何影响结果。
- 随机事件承担了人生主驱动，导致玩家像在观看随机人生播放器。
- 报告和结算缺少因果解释，难以看出行动、属性、路线和结果之间的关系。

P7 的目标不是扩写大量剧情，也不是一次性实现天赋、道具、完整世界观或新 UI。P7 只建立一个可扩展的主动人生闭环，使后续天赋、道具、世界观、区域、势力等系统能自然接入，而不是继续堆在随机事件表上。

## 2. 核心判断

P7 采用“统一规划、分阶段实施”的方式。所有方向进入同一份设计边界，但业务实现必须拆成小步交付。

核心循环调整为：

```text
阶段目标 -> 玩家选择本期行动 -> 行动产生短期结果 -> 随机/剧情事件扰动 -> 属性与关系变化 -> 更新下一期可选方向
```

随机事件不再是人生主驱动。随机事件负责制造江湖无常、机会、诱惑、惩罚和意外；玩家主动行动负责承载规划、养成和方向选择。

属性解释不采用频繁弹窗。属性意义主要放在属性面板和选择界面：

- 属性面板解释能力、趋势、可见门槛和自我认知程度。
- 选择界面解释当前行动的条件、风险、收益和锁定原因。
- 结算界面解释本次结果的关键因果。

## 3. 目标

1. 建立玩家主动选择本期行动的机制，使人生可以被规划。
2. 将普通推进从“一事件一年”调整为月、季度或短阶段，重大节点才跨年。
3. 建立显性属性、隐性属性和自我觉悟的认知模型。
4. 将属性从后台数值改造成玩家可理解的能力系统。
5. 让选项具备收益、代价、风险和机会成本，避免明显最优项碾压。
6. 将随机事件降级为行动后的扰动、机会或压力源。
7. 让报告能解释行动、属性、路线、选择和结果之间的因果。
8. 为后续天赋、世界观、道具系统预留稳定接入点。

## 4. 非目标

- 不一次性实现完整天赋系统。
- 不一次性实现完整道具系统。
- 不一次性扩写完整世界观、区域、势力和时代设定。
- 不重做整体视觉风格。
- 不改变 P6B 的后端、存档、API 或服务权威边界。
- 不批量重写全部事件文件。
- 不为了兼容旧行为保留错误的年度推进兜底。
- 不把隐性属性做成纯调试字段；隐性属性必须服务玩家体验。

## 5. 范围

### 5.1 In Scope

- 当前事件驱动、时间推进、属性消费、选项条件和报告输出的只读基线盘点。
- 主动行动分类、行动周期、行动收益、风险和扰动规则。
- 时间粒度规则：月、季度、短阶段、年度和重大节点的使用边界。
- 属性认知模型：显性属性、隐性属性、自我觉悟、模糊描述和具体数值可见度。
- 属性面板信息结构：属性用途、趋势、门槛、近期变化、可解锁方向。
- 选择界面信息结构：收益、代价、风险、条件、锁定原因、机会成本。
- 报告因果链：行动计划、属性变化、事件扰动、路线推进、结局权重。
- 扩展接入点：天赋、道具、世界观、区域、势力和身份系统。
- 针对当前已发现的条件缓存属性遗漏问题建立修复 story。

### 5.2 Out of Scope

- 大规模新增事件内容。
- 全量剧情重写。
- 完整经济系统、装备系统、背包系统。
- 完整开放世界地图。
- 账号、联网、云存档、小程序或管理后台。
- 对未批准阶段的业务代码提前实施。

## 8. 验收门禁

P7 每个实现 story 至少需要：

- TypeScript 类型检查通过。
- 对应 story 的单元或集成测试通过。
- 若涉及报告或模拟器，必须生成可复现报告。
- 若涉及 UI，必须通过本地浏览器验证主流程没有阻塞。
- 若涉及时间推进，必须验证普通事件不会强制推进一年。
- 若涉及属性条件，必须验证条件缓存不会因遗漏属性产生旧结果。

P7 收口门禁：

- 固定种子或固定输入下可以完成 0-30 岁主动行动路径。
- 报告中随机扰动不再替代玩家行动成为主驱动。
- 属性至少在三个场景中产生玩家可见的能力意义。
- 选项至少在三个场景中体现收益、代价、风险或机会成本。
- 报告能明确列出年度跳跃、锁定选项、属性门槛和关键因果。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 一次性实现范围过大 | 可靠性下降，难以定位问题 | 总 PRD 统一规划，按 story 小步实施 |
| 主动行动层变成开放世界 | 范围失控 | P7 只做最小行动闭环，不做地图和完整世界观 |
| 属性认知过度透明 | 失去探索感 | 显性/隐性属性分层，自我觉悟控制可见度 |
| 属性认知过度隐藏 | 玩家仍然无法规划 | 行动门槛、结果因果和属性面板必须给足可理解线索 |
| 选项平衡变成数值平均 | 每个选项都无聊 | 平衡重点是不同吸引力，不是数值相等 |
| 随机事件仍然抢走主导权 | 回到随机播放器 | 设置扰动占比和回流规则 |
| 报告只变成更多指标 | 仍然无法指导体验 | 报告必须定位具体入口和因果，不只统计数量 |

## 10. 实施顺序

1. 先完成 US-001 到 US-005，冻结 P7 基线、当前缺口和守门边界。
2. 再完成 US-006 到 US-012，定义主动行动模型、增加最小行动目录、解析器和测试。
3. 再完成 US-013 到 US-015，将主动行动接入主流程并记录行动历史。
4. 再完成 US-016 到 US-018，修复主流程和模拟器的年度推进问题，并增加回归检查。
5. 再完成 US-019 到 US-026，建立属性显隐、自我觉悟、属性面板语义和条件缓存修复。
6. 再完成 US-027 到 US-031，建立选项权衡、条件解释、锁定展示和行动风险摘要。
7. 再完成 US-032 到 US-038，接入随机扰动并让报告展示行动、时间和属性因果。
8. 最后完成 US-039 和 US-040，冻结扩展边界并做 P7 收口验证。

每个 story 单独实施、单独验证、单独记录结果。任何需要扩大到天赋、道具、世界观完整实现的发现，都记录为后续 PRD，不在 P7 中直接扩散。
